# ตั้งค่าแม่น้ำกลาง (Supabase)

ถ้าไม่ตั้งค่า เว็บทำงานได้ตามปกติ แต่กระทงของ "เพื่อนร่วมแม่น้ำ" จะเป็นข้อความสมมติและกระทงของคุณลอยเฉพาะในเครื่อง

1. สร้างโปรเจกต์ที่ Supabase
2. เปิด SQL Editor แล้วรันไฟล์ `supabase/migrations/0001_kratongs.sql`
   - เปิด RLS ไว้โดยไม่มี policy จึงเข้าถึงตารางจากเบราว์เซอร์ตรงๆ ไม่ได้ ทุกอย่างผ่าน API ของเว็บเท่านั้น
3. ตั้ง environment variables ตอน deploy (ดู `.env.example`)
   - `SUPABASE_URL`: Project URL
   - `SUPABASE_SERVICE_ROLE_KEY`: service_role key เป็นความลับ ห้ามขึ้นต้นด้วย `NEXT_PUBLIC_` และห้าม commit
   - `IP_HASH_SALT`: ข้อความสุ่มยาวๆ ใช้ hash IP ตอนจำกัดอัตรา (ไม่เก็บ IP จริง)
4. (แนะนำ) ตั้ง pg_cron ลบกระทงเก่า ตามคอมเมนต์ท้ายไฟล์ migration

## กติกาที่ระบบบังคับใช้ (src/lib/river/service.ts)
- ลอยได้ 5 ใบ/10 นาที ต่อเบราว์เซอร์ และ 15 ใบ/10 นาที ต่อ IP
- อนุโมทนา/รายงานได้ใบละครั้งต่อเบราว์เซอร์ และรวมไม่เกิน 60 ครั้ง/10 นาที
- กระทงที่ถูกรายงานครบ 3 ครั้งจะถูกซ่อนอัตโนมัติ
- คำหยาบ ลิงก์ อีเมล เบอร์โทร ในคำอธิษฐานจะถูกปฏิเสธ (src/lib/profanity.ts)

## ข้อควรรู้
- ตัวกรองคำหยาบเป็นรายการคำ จับได้ไม่ครบ ควรเปิดดูตาราง `kratongs` ที่ `reports > 0` เป็นระยะ
  หรือสั่งซ่อนเองด้วย `update kratongs set hidden = true where id = '...'`
- ระบบอ่าน IP จาก header `x-forwarded-for` ถ้า deploy หลัง proxy/CDN ที่เชื่อถือได้ (เช่น Vercel) จะใช้ได้ทันที
  ถ้าเปิดเซิร์ฟเวอร์ตรงๆ ผู้ใช้ปลอม header ได้ ให้จำกัดที่ชั้น proxy แทน
- หน้าเว็บดึงรายการใหม่ทุก 15 วินาที (ไม่ได้ใช้ Realtime)
